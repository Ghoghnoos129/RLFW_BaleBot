# ربات لیگ کتابخوانی (پیام‌رسان بله)

ربات مدیریت کامل «لیگ کتابخوانی» طبق طرح ارسالی شما: ثبت‌نام کاربران، ثبت دقایق مطالعه،
محاسبه خودکار امتیاز (۲۰ دقیقه برای خانواده دارای فرزند / ۲۵ دقیقه برای بدون فرزند)،
امتیاز کتاب‌های ویژه، سقف ۱۵۰ امتیاز، تبدیل هر ۵ امتیاز به یک کد قرعه‌کشی، و در پایان فصل
قرعه‌کشی خودکار دو جایزه با فرمول «۵۰۰هزار پایه + ۱۰۰هزار به ازای هر ۱۰ کد، سقف ۱.۵ میلیون».

هیچ وابستگی سنگینی ندارد: فقط پایتون + `requests`، و دیتابیس SQLite (یک فایل ساده، نیازی به
نصب و راه‌اندازی دیتابیس جداگانه نیست).

## ۱. گرفتن توکن ربات

۱. در اپلیکیشن بله وارد بخش ساخت ربات شوید (از داخل بله، گزینه‌ی «ربات‌ساز» / BLB) و یک ربات
   جدید بسازید. در پایان یک **توکن** به شما داده می‌شود.
   راهنمای رسمی و به‌روز: docs.bale.ai
۲. توکن را نگه دارید؛ در مرحله بعد در فایل `.env` قرار می‌گیرد.

## ۲. نصب روی سرور (VPS) — با Docker (پیشنهادی)

ربات به‌صورت یک ایمیج Docker سخت‌سازی‌شده (کاربر غیر-روت، فایل‌سیستم read-only، بدون
هیچ Linux capability اضافه، محدودیت CPU/RAM) اجرا می‌شود:

```bash
cd reading-league-bot
cp .env.example .env
nano .env   # BALE_TOKEN و ADMIN_SETUP_CODE را پر کنید

docker compose up -d --build
docker compose logs -f bot   # مشاهده لاگ زنده؛ باید «ربات با موفقیت متصل شد» دیده شود
```

### تعیین ادمین (بدون نیاز به دانستن آیدی عددی)
در بله اپی نیست که آیدی عددی‌تان را نشان بدهد؛ به‌جایش یک **کد مخفی** در `.env` می‌گذارید:
```env
ADMIN_SETUP_CODE=یک-رمز-دلخواه
```
بعد از بالا آمدن ربات، همین رشته را عیناً به‌عنوان یک پیام به ربات بدهید — همان لحظه
به عنوان **«مدیر اصلی»** ثبت می‌شوید. اگر نفر دیگری هم بخواهید ادمین باشد، او هم همین
کد را بفرستد؛ او فقط «ادمین» عادی می‌شود (نه مدیر اصلی).

برای امنیت بیشتر، بعد از ثبت مدیر(ها)، مقدار `ADMIN_SETUP_CODE` را از `.env` پاک یا
عوض کنید (`docker compose up -d --build` دوباره) تا دیگران نتوانند با همان کد خودشان
را ادمین کنند.

فقط مدیر اصلی می‌تواند با دستور `/حذف_مدیر <آیدی>` یک ادمین دیگر را حذف کند (آیدی‌ها از
`/لیست_مدیرها` قابل مشاهده‌اند). اگر از قبل آیدی عددی کسی را می‌دانید، روش جایگزین/پیشرفته
`ADMIN_IDS` در `.env` هم همچنان کار می‌کند و آن فرد را مستقیم «مدیر اصلی» می‌کند.

با `restart: unless-stopped` در `docker-compose.yml`، ربات با ری‌استارت سرور هم خودش
بالا می‌آید و اگر کرش کند خودکار دوباره اجرا می‌شود — نیازی به سرویس systemd جداگانه نیست.
جزئیات سخت‌سازی امنیتی کانتینر در کامنت‌های داخل `Dockerfile` و `docker-compose.yml` توضیح
داده شده.

### دیپلوی خودکار با وبهوک گیت‌هاب (ریپوی پرایوت)
اگر می‌خواهید با هر `push` به گیت‌هاب، ربات خودش روی سرور به‌روز و ری‌استارت شود، راهنمای
کامل (ساخت Deploy Key، دریافت‌کننده وبهوک با تایید امضای HMAC، Nginx+TLS، و sudoers محدود
برای جلوگیری از دسترسی روت به فرآیند اینترنتی) در **[`deploy/README.md`](deploy/README.md)**
آمده است.

### اجرا بدون Docker (جایگزین، فقط در صورت نیاز)
اگر به هر دلیلی نمی‌خواهید از Docker استفاده کنید، همان روش قدیمی (پایتون مستقیم + یک
سرویس systemd نمونه در `systemd/reading-league-bot-no-docker.service.example`) هم
جواب می‌دهد؛ ولی سخت‌سازی‌های این بخش (کاربر غیر-روت، فایل‌سیستم read-only و غیره) را ندارد.

## ۳. استفاده برای کاربران عادی

- `/start` → ثبت‌نام (نام و نام خانوادگی + دارد/ندارد فرزند)
- از منوی پایین صفحه:
  - **📖 ثبت مطالعه** — وارد کردن دقایق مطالعه؛ اگر کتاب ویژه‌ای در فصل جاری تعریف شده
    باشد، بعد از ثبت دقیقه از کاربر پرسیده می‌شود کتابی را تمام کرده یا نه.
  - **🏆 کارنامه من** — دقیقاً مطابق فرمتی که در طرح آمده (نام، فرزندان، دقیقه مطالعه،
    کتب تکمیل‌شده، امتیاز، دقیقه لازم برای امتیاز بعدی، تعداد کد، امتیاز لازم برای کد
    بعدی، رتبه در فصل، مجموع جایزه‌های برده‌شده تاکنون)
  - **📚 کتاب‌های ویژه این فصل** — لیست کتاب‌ها و امتیاز هرکدام
  - **❓ راهنما**

## ۴. دستورات مدیریتی (فقط برای ادمین‌ها)

| دستور | کاربرد |
|---|---|
| `/فصل_جدید <نام فصل>` | شروع فصل تازه (فصل قبلی خودکار بسته می‌شود) — مثال: `/فصل_جدید پاییز ۱۴۰۴` |
| `/افزودن_کتاب <عنوان> \| <امتیاز>` | افزودن کتاب ویژه — مثال: `/افزودن_کتاب طرح کلی اندیشه اسلامی در قرآن \| 10` |
| `/حذف_کتاب <شناسه>` | حذف یک کتاب ویژه |
| `/لیست_کتاب‌ها` | نمایش کتاب‌های فصل جاری با شناسه |
| `/گزارش_فصل` | جدول کامل امتیازات همه شرکت‌کنندگان فصل جاری |
| `/پایان_فصل` | بستن فصل جاری: امتیازها آرشیو می‌شوند، قرعه‌کشی بین دارندگان کد انجام می‌شود و برندگان هم در چت ادمین و هم با پیام خصوصی مطلع می‌شوند |
| `/لیست_کاربران` | لیست و تعداد کل ثبت‌نام‌شدگان |
| `/لیست_مدیرها` | نمایش مدیر اصلی و ادمین‌های ثبت‌شده با آیدی عددی هرکدام |
| `/حذف_مدیر <آیدی عددی>` | فقط برای مدیر اصلی: حذف یک ادمین عادی (مدیر اصلی حذف‌شدنی نیست) |

دستورات ادمین نیازی به ثبت‌نام قبلی به‌عنوان شرکت‌کننده لیگ ندارند؛ همین که کسی ادمین
باشد (چه با `ADMIN_SETUP_CODE` چه با `ADMIN_IDS`)، این دستورات برایش کار می‌کنند.

اگر دستوری را بدون پارامتر بفرستید (مثلاً فقط `/فصل_جدید`)، ربات در پیام بعدی از شما
همان مقدار را می‌پرسد.

## ۵. نکات پیاده‌سازی طرح شما

- **امتیاز مطالعه:** `دقیقه ÷ ۲۰` (دارای فرزند) یا `دقیقه ÷ ۲۵` (بدون فرزند)، باقیمانده
  برای فصل بعد منتقل نمی‌شود چون در پایان فصل همه چیز صفر می‌شود (طبق طرح).
- **امتیاز کتاب:** فقط با تایید «اتمام کامل» کتاب از طریق دکمه ثبت می‌شود و هر کتاب فقط
  یک‌بار برای هر کاربر قابل ثبت است.
- **سقف ۱۵۰ امتیاز:** در همه محاسبات (کارنامه، گزارش فصل، قرعه‌کشی) اعمال می‌شود.
- **کد قرعه‌کشی:** `امتیاز ÷ ۵` (رند به پایین؛ باقیمانده کمتر از ۵ امتیاز طبق طرح از بین می‌رود).
- **جایزه:** پایه ۵۰۰٬۰۰۰ تومان برای هرکدام از ۲ برنده؛ به ازای هر ۱۰ کد مجموع
  شرکت‌کنندگان، ۱۰۰٬۰۰۰ تومان به *هر* جایزه اضافه می‌شود (یعنی ۲۰۰٬۰۰۰ تومان مجموعاً)،
  تا سقف ۱٬۵۰۰٬۰۰۰ تومان برای هر جایزه.
- **قرعه‌کشی وزن‌دار:** هرچه کد بیشتری داشته باشید شانس بیشتری دارید (دقیقاً مثل طرح:
  "بقیه با امتیاز کم حداقل شانس برنده شدن را دارند")، چون هر کد یک بلیط جداگانه در
  قرعه‌کشی است.
- داده‌ها در فایل SQLite (`data/league.db`) ذخیره می‌شوند — پشتیبان‌گیری یعنی فقط کپی
  همین یک فایل.

## ۶. تست منطق بدون نیاز به توکن واقعی

```bash
python tests/test_flow.py
```
این اسکریپت یک سناریوی کامل (ثبت‌نام، ثبت مطالعه، اتمام کتاب، سقف امتیاز، گزارش فصل،
پایان فصل و قرعه‌کشی) را شبیه‌سازی و نتایج محاسباتی را با مقادیر درست مقایسه می‌کند — بدون
نیاز به اتصال اینترنت یا توکن واقعی. همین تست روی این پروژه اجرا و با موفقیت پاس شده است.

## ساختار پروژه

```
reading-league-bot/
├── run.py                  # نقطه اجرا (polling loop)
├── requirements.txt
├── .env.example
├── app/
│   ├── config.py           # تنظیمات و قوانین امتیازدهی (از .env)
│   ├── db.py                # لایه SQLite
│   ├── bale_api.py          # ارتباط با tapi.bale.ai
│   ├── scoring.py           # محاسبه امتیاز/کد/جایزه
│   ├── keyboards.py         # کیبوردهای شیشه‌ای و منو
│   ├── texts.py             # متن پیام‌ها
│   └── handlers.py          # منطق اصلی گفتگو و دستورات ادمین
├── systemd/reading-league-bot.service
└── tests/test_flow.py
```

## سوالات بعدی که ممکن است پیش بیاید

- اگر خواستید عدد قوانین (مثلاً سقف ۱۵۰، فاصله ۲۰/۲۵ دقیقه، مبلغ جوایز) را بعداً تغییر
  دهید، کافی‌ست مقادیر بالای فایل `app/config.py` را ویرایش و ربات را ری‌استارت کنید.
- اگر بعداً خواستید خروجی اکسل از گزارش فصل هم داشته باشید یا پنل وب مدیریتی اضافه شود،
  بگویید تا به همین پروژه اضافه‌اش کنم.
